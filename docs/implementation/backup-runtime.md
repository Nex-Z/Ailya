# 备份恢复与本地稳定启动

日期：2026-10-02。在插件首版后继续实现；不修改冻结标签和开发 Skills。

## 设置中的备份恢复

「设置 → 会话与存储」支持创建备份、下载、检查本地 SQLite 备份路径，以及从备份列表恢复。正式备份文件位于数据目录的 `backups/`；备份是数据库的一致性快照，不是另一套业务主库。

创建使用 SQLite `VACUUM INTO`，包含会话、任务、事件、附件字节、模型及加密凭据、权限、记忆和向量、扩展、Skills、插件包及任务版本、定时任务和运行记录。外部工作空间文件不包含在内，恢复也不回滚这些文件。浏览器尚未发送的草稿及展示偏好不属于数据库备份。数据库整体没有加密，下载的备份需按私有数据保存；模型 DPAPI 凭据换 Windows 用户/机器后可能需要重新填写；MCP 的整份配置为 DPAPI 密文，无法解密时预览会拒绝恢复，需在原 Windows 用户下另行迁移配置。

恢复先将来源的一致性副本放入 Core 私有目录，检查 SQLite 完整性、受支持的迁移序列、实际表/索引结构、外键关系、向量字节长度、结构化记录和会话基本字段。只支持当前已知的 v1–v11 数据库，旧版在副本上迁移，不修改来源。v10→v11 恢复已实测，其他早期版本的恢复入口尚未逐版验收。结构兼容不保证每个业务配置均可运行；运行时初始化失败另有回退。

预览展示数据数量；来源文件在预览后修改不改变待恢复副本。副本带哈希校验，有效期 10 分钟，最多 5 份未确认预览。用户确认后再次核对状态，先创建当前库的自动备份，再关闭旧 Core 数据连接、保留独占锁、原子替换数据库、重建 Core 并使浏览器重新连接。其他标签页重新拉取快照，事件游标可以回退到恢复后的值。启动失败会从恢复前备份还原并重新启动；如果磁盘等故障同时阻止回退，则保持服务不可用，不以空库顶替。

任务、插件安装、压缩或其他 HTTP 请求未完成时拒绝恢复。恢复期间拒绝新的 API 与 WebSocket 连接；Core 调度先停止，旧后台索引关闭后才替换。恢复后沿用既有启动语义：运行中任务标中断、旧授权失效、问题截止时间保留、错过的定时任务不补跑；未来启用的定时任务仍按配置运行。插件安装状态和包版本随库恢复，因此只恢复可信备份。

当前库的记忆删除/抑制记录在预览和最终替换前应用到副本，清理对应原文、向量和派生摘要，防止旧备份复活已经删除的记忆。既有备份原文件不改写；在另一台没有最新删除记录的机器上恢复，无法推断该机器未持有的删除历史。

本版不提供自动备份计划、备份删除/保留策略、远程上传恢复和备份加密。单个恢复来源限制 1 GB。崩溃遗留的预览目录可能需要人工清理；取消预览、正常退出及过期检查会清理所管理的副本。原子替换避免半个主库，不代表磁盘损坏、断电或独立外部程序写库都可自动恢复。

## 一个 Core 提供网页和 API

```powershell
npm ci                 # 首次安装依赖
npm start              # 构建，然后后台启动并检查健康状态
npm run status         # 查看地址、PID、数据路径及 schema
npm run stop           # 空闲时正常关闭；有执行任务则拒绝
# 或从 PowerShell 运行，启动成功后打开浏览器
.\Start-Ailya.ps1
.\Stop-Ailya.ps1
```

正式本地入口为 `http://127.0.0.1:4317`，Core 直接提供 `dist` 网页及同源 API/WebSocket，不再要求同时开 Vite。源码开发仍可用 `npm run core` 与 `npm run dev`，原 5173 入口保持兼容。

启动器使用当前 Bun、Node/npm 和现有源码依赖；检查已存在的服务和数据目录，重复启动复用匹配的 Core。端口为其他服务或另一数据目录占用时拒绝操作。尚无服务时先构建，构建失败不启动；后台进程隐藏窗口，日志在数据目录 `logs/`，启动检查实际 HTTP 健康状态。停止通过带实例标识的本机 API 正常退出，不依据任意 PID 强杀。

`AILYA_DATA_DIR`、`AILYA_WORKSPACE`、`AILYA_PORT` 可在启动环境中指定；默认数据仍为 `%LOCALAPPDATA%\Ailya\data\ailya.sqlite`，独立于源码和构建产物。升级代码后应先空闲停止、安装匹配依赖，再 `npm start` 重新构建；迁移沿用升级前自动备份，不删除数据。停止/状态命令需使用与启动一致的端口和数据目录。当前只做本机启动，不安装系统服务、开机自启、进程守护、自动更新或可分发安装包；尚未验证脱离源码和 node_modules 的发布形态。
