# 微信与语音输入首版（2026-10-02）

状态：代码与隔离链路已接入；微信真实接口获取二维码成功。真实账号扫码后的双向收发，以及用户选择的语音服务识别效果，尚待验证。以下测试不替代这两项验收。

## 微信

设置 → 远程 IM → 添加 IM → 扫码绑定。支持多个独立微信账号。二维码由 Core 请求并在本地编码显示，登录令牌使用 Windows DPAPI 加密后写入 SQLite，不返回前端。扫码默认只允许扫码者，允许名单可编辑；选择“仅允许私聊”后，允许该账号收到的其他私聊，群聊不处理。

根据 [腾讯公开协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md) 独立实现 HTTP 适配器。本次核对源码 `24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c`，包版本 2.4.9。使用扫码状态轮询、验证码、微信域名内跳转和 getupdates 长轮询，无需公网入站端口。认证后配置 bot_agent 为 Ailya/0.0.0。第三方账号是否可用仍取决于微信服务响应。

- SQLite v12 保存账号、加密凭据、收信游标、账号/用户对应会话、收件和发件记录。迁移前自动备份；旧会话和向量不重置。
- 每个账号及私聊用户拥有独立会话，使用本地默认工作空间、Ailya 和当前默认模型。首次消息后保持会话上下文，默认权限始终生效。
- 文本进入既有 Core/Pi 运行链路，浏览器关闭不影响收发。模型最终答复、错误、停止、授权和提问通过持久化发件记录返回微信。长文本分段。
- `/帮助`、`/新会话`、`/停止`、`/允许 请求ID`、`/会话允许 请求ID`、`/拒绝 请求ID`、`/回答 问题批次ID 答案JSON`、`/拒答 问题批次ID` 接入原有状态机；跨账号、跨用户、过期请求不能授权或续跑。问题通知包含答案 JSON 模板，30 秒截止时间不改变。
- 平台消息 ID 保留 uint64 精度，按账号去重。运行中的会话按序处理后续普通消息，控制指令优先处理；停止/新会话会取消此前积压的消息。崩溃中断的处理中消息不自动重执行；原任务由 Core 标记中断。
- 发送成功表示接口接受，不能证明手机端已展示。网络失败或发送中崩溃标为结果不确定，不自动重发；设置显示未确认送达数量，结果仍在网页会话中。
- 停用/删除账号会取消登录、停止轮询和所属任务，取消待处理收件及待发回复。已完成的外部操作不回滚，已开始的 HTTP 发送不能保证撤回。
- 备份恢复后所有 IM 账号停用，取消备份里的待处理消息，避免自动重放外部副作用；需手动启用。普通 Core 重启可恢复已启用账号的轮询。异机 DPAPI 凭据需要重新扫码。

当前未实现其他 IM 平台、群聊、微信图片/文件/视频收发、主动推送、微信媒体解码和完整富文本卡片。微信消息若自带语音转写文本，可按文字接收；未带转写的媒体明确提示不支持。旧原型 localStorage 配置保留，不自动绑定真实账号。

## 语音输入

设置 → 模型与连接 → 语音识别，填写服务基础地址、模型及 Key。Core 向地址下的 `/audio/transcriptions` 发送 multipart 请求，包含 `model`、`file`、`response_format=json`，服务须返回 `{text:string}`。支持无 Key 的本地接口；更换地址时不能沿用旧地址的密钥。配置与加密 Key 由 SQLite 管理，Key 不交给浏览器。

按住输入框麦克风录音，松开后转写到当前输入框，用户检查后按发送；键盘聚焦麦克风可按住空格或 Enter。录音期间图标变红，转写期间显示等待状态；Escape、窗口失焦、切换会话和点击转写中的按钮可取消，迟到响应不写入其他草稿。

浏览器通过 getUserMedia / AudioWorklet 采集 16 kHz 单声道 PCM WAV，最多两分钟。Core 校验 WAV 长度、格式和时长，再向配置服务转发。音频不写入正式会话或文件；识别文字在发送前只是草稿。浏览器需要麦克风权限及安全上下文（本机 localhost 或 HTTPS）。没有配置、权限拒绝、无识别文本和服务失败均反馈真实错误。

不包含 TTS、实时双向语音或内置离线模型。接口配置不等于服务兼容验收；本次用户决定稍后填写服务信息，尚未验证实际中文识别质量、延迟和手机硬件录音。
