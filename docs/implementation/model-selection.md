# 显式模型选择持久化

2026-09-28。用户指出新会话总选第一个模型。根因为 draft 初始化“默认模型”、ContextSelect 自动选择第一项，且 setContext 只修改浏览器瞬时状态，未发送的会话模型选择没有持久化。

复用 SQLite `core_settings` 存储 `preferred-model`，不增加迁移、不使用 localStorage。只有用户主动选择调用 `POST /api/model-selection`：Zod 校验、验证模型仍配置、拒绝修改运行中会话，再原子保存全局偏好和已有会话 context，并发布会话事件。没有发送的草稿更新全局偏好；新会话（包括复用空白草稿）使用上次选择；已有会话保持自身模型。快照返回有效偏好，Core 的默认模型解析也使用它；尚未选择或已删除模型时才回退可用首项。

保存期间禁用模型选择和发送，避免保存未完成时发往旧模型；API 失败显示错误而不假称保存成功。保留原下拉样式、厂商分组及运行时禁用规则。不是长期记忆或推断偏好功能，不改变权限、调度或历史模型请求。

验证：`tests/core/model-selection.test.ts` 使用临时 SQLite 验证重启保持、旧会话选择保持、无效/运行中修改拒绝、缺失模型回退；正式 Core/Pi HTTP 模型请求检查实际 model 字段。`tests/model-selection-live.spec.ts` 使用真实 Core/浏览器和独立测试会话验证新会话继承、已有会话隔离、未发送前选择保存、刷新和窄屏，测试后恢复原全局选择并删除自己的会话。`tests/context-model.spec.ts` 保留 UI 隔离测试，并明确替换新保存接口，避免 mock 会话向真实 Core 写配置。

Self-review：自动展示首项不再写入偏好；事务内同时保存设置和会话，提交后才发布通知；保存结果绑定发起时会话 ID，切换会话不会写错目标；执行中的 Core 会话也有服务端校验。同一作者自审，独立审查未执行，人工复核 pending。冻结标签和既有工作区修改保留。
