# 长期记忆首版

日期：2026-10-02。基线 `0341445`，本记录对应其后工作区实现。self-review，未执行独立审查，人工复核 pending。产品记忆存于 Core SQLite，与仓库 Skills、开发经验及 Codex 全局记忆无关。

## 用户入口

设置 → 数据 → 记忆：搜索、按状态筛选、新增、编辑、删除，查看来源会话、原文摘录、作用域及版本，确认或拒绝 AI 候选。内容类型为事实、偏好、经验；范围可选工作空间、全局、已存在的主会话；支持到期日期。默认新记录属于当前工作空间。

按用户复核意见，设置仅保留默认开启的“使用记忆”，控制主动检索和注入。AI 自动维护为内置行为，不提供单独开关；关闭使用不停止维护，手动管理始终可用。旧配置中的 `learningEnabled` 不再生效，兼容旧客户端提交但不返回该字段。设置由 Core 保存，刷新和重启保留；页面提供刷新按钮获取其他任务产生的候选。

AI 通过 Pi 的 `remember_memory`、`search_memory`、`forget_memory` 维护和查找记忆，普通用户无需指定工具名。检索在每次执行中读取使用开关。明确的非敏感“记住／以后这样”可直接激活，Core 验证引文来自本次真实用户消息，并直接保存该引文；一般推断进入待确认，不立即注入模型。“这次／暂时／不要记”等请求拒绝持久化，常见凭据格式被拦截。附件、工具结果和子任务指令不能作为用户消息来源；子 Agent 和定时任务只获得检索工具。

用户编辑或确认的记录优先。同主题 AI 修改只能提出候选，不能借再次修改候选覆盖用户记录。AI 更新带版本校验；过期编辑提示刷新。确认新记录会移除同范围、同主题的旧有效记录，记录无正文的变更元数据。AI 自动新增仅限当前工作空间；全局或会话范围由设置管理。主题不同的语义冲突仍依赖模型判断与用户复核，尚无自动冲突裁决器。

## 请求与存储

SQLite v9 新增 `memories`、`memory_sources`、`memory_audit`、`memory_uses`、`memory_suppressions`、`memory_deletions`、`memory_index_jobs`。原文、版本、状态、来源关系、到期时间、使用关系、删除抑制及索引队列均由 Core 管理。

自动检索先限制有效范围、状态和有效期，再处理同主题优先级和相关性排序。最多注入 8 条、正文合计 6000 字符；英文关键词与中文双字词检索可独立工作。偏好可作为限额内的默认参考。记忆引用是非权威数据，不能授权执行或覆盖当前用户指令。模型请求审计保存 `memoryReferences` ID / 版本，记忆计入压缩预算；等待压缩期间若记忆变化，会重新投影并检查预算。

API 均位于现有本机 Core 来源限制下：

- `GET /api/memories`：列表、来源、配置和索引状态。
- `POST /api/memories`：严格 Zod 校验的新增或版本化编辑。
- `POST /api/memories/:id/decision`：确认或拒绝指定版本的候选。
- `DELETE /api/memories/:id`：删除指定版本。
- `POST /api/memories/config`：使用及 embedding 配置。
- `POST /api/memories/reindex`：重新生成索引。

## Embedding 与删除

检索设置支持独立的 OpenAI 兼容 embedding 地址、模型及可选密钥，默认关闭语义检索。不假设聊天厂商提供 embedding。启用前页面说明生效记忆与查询文本将发送到所配置的服务；密钥用 Windows DPAPI 加密，不返回前端，更换地址时不自动携带旧密钥。未配置、请求失败或索引未准备好时保留关键词路径；索引失败原因及待处理数量可在设置查看。

embedding 网络请求在 SQLite 事务外进行，限时并可取消；队列持久化，重启恢复未完成任务。回写前检查内容版本、状态、有效期和索引配置版本。sqlite-vec 查询在授权候选集、当前模型、索引修订和维度内排序。模型配置变化清除旧派生向量并重建，原文保留；维度不一致拒绝写入并显示失败，可重建恢复。

删除同时清理实体、向量、索引任务和来源关系，取消相关压缩并使使用过该记忆的摘要及分段缓存失效。保留无正文的删除 ID 和来源哈希抑制记录，避免同一来源再次学习。晚到 embedding 不会恢复已删除内容。删除来源会话会删除该会话范围记忆和仍由 AI 管理的来源记忆；用户已编辑／确认的独立记录保留，移除失效来源关系。

删除记忆不删除原始聊天、任务执行审计、已生成回复或已经送到模型的请求；同一旧会话仍可能从原有历史知道相关事实。关闭记忆使用也不擦除聊天历史。若需去除原始来源，应同时删除相应会话。原始请求审计遵循现有会话删除生命周期。

恢复辅助接口 `deletionLedger()` / `applyDeletionLedger()` 已覆盖“旧备份 + 最新删除账本”的合并恢复测试。产品尚无备份恢复 UI；手动覆盖数据库而丢弃最新账本会丢失后续删除决定，不能称为安全恢复。磁盘上既有备份不会被自动改写或抹除。

## 验证与限制

Windows / Bun 1.4.2 / sqlite-vec 0.1.9：

- `npm run build`、`npm run lint`；构建仍有既有大 chunk 提示。
- `bun test tests/core`：包含记忆与索引的行为测试，覆盖明确记忆、候选、用户优先、开关、跨空间／会话、时效、版本冲突、删除抑制、迟到回写、升级、重启和账本恢复。
- `bun scripts/session/memory-browser.ts`：隔离 Core + 正式构建，验证设置 CRUD、刷新保留、开关、候选确认及 1465px / 390px 界面，无页面异常。
- `bun scripts/session/memory.ts record`：真实 DeepSeek v4 Pro，9 次请求。模型自行保存项目标记，新会话用真实文件工具写出 `LILAC-73`；手动纠正后另一新会话写出 `LILAC-84`；删除后再开会话回答不知道，审计无记忆引用。候选保存在忽略目录 `artifacts/session-candidates/memory-v1.json`，没有自动升级为受版本管理基线。
- `bun scripts/session/memory.ts replay` 与 `bun scripts/session/verify-memory.ts`：逐请求匹配并完全消费录制，检查实际 SQLite 引用和独立文件预期；格式变化、请求变化、缺失／多余调用、错误文件预期这 5 个反例必须失败。
- 本机实际数据库升级至 v9，升级前生成一致性备份；升级前后 5 会话、12 任务、1 附件、5 transcript 保留。

真实聊天模型闭环已验证；embedding HTTP 与向量生命周期使用本地确定性服务验证，尚未获得真实 embedding 服务配置，未宣称语义质量或真实 embedding 链路已验收。当前默认关键词检索可用。
