# Review 方案

## 范围与输出

先读取当前 diff（含 staged、unstaged、untracked），记录基线和待审版本。对比目标行为及 production-contract，不擅自改变验收标准。输出：结论、已确认缺陷、证据缺口和建议；没有发现缺陷就直说，并说明未验证的部分。

每条缺陷使用稳定 ID，例如 R-01：严重度、位置、触发条件、可观察后果、复现/证据、建议修复、回归用例。推测标记待验证，不能作为已确认缺陷；格式喜好不冒充阻塞问题。

- P0：数据损毁、凭据泄漏或权限绕过等紧急问题。
- P1：承诺功能失效、任务生命周期错误、升级丢失数据。
- P2：局部交互/异常处理问题，有替代路径但违反验收条件。
- P3：可选改善，不以此无限返工。

P0/P1 未关闭不进入正式验收；P2 若影响本次验收也必须修复，否则说明影响并由用户决定是否延期。作者不得自行把需求缺口降成 P3。缺陷状态：open、fixed-unverified、verified、deferred（附用户决定）、rejected（附反证）。

## 按风险追踪

| 改动 | 必查问题 | 所需证据 |
|---|---|---|
| 会话/任务/子 Agent | session/task/attempt 是否区分？停止会否继续写？晚到事件会否串会话？ | 状态序列、取消后外部状态、重连/重启 |
| 问题面板 | 批次截止时间是否持久？超时与提交竞态？拒答是否停止？ | 虚拟时钟边界、Core 事件、回答一次生效 |
| 文件/重试 | 原操作是否已生效？覆盖消息是否重复写？差异是否源自实际文件？ | 文件前后内容、事件、重复请求 |
| SQLite/向量 | 迁移、模型维度、作用域、删除一致性、备份是否有效？ | 旧库升级、固定向量与范围检索、恢复 |
| 权限/IM | 绕过 UI 直接 API 是否仍受控？账号之间是否隔离？ | 拒绝路径及真实执行入口 |
| UI | 是否保留冻结交互？推荐未代选？窄屏/键盘是否可用？ | 可操作页面、截图和浏览器行为 |
| 模型/扩展 | 真实输出/插件能否经发布入口运行？资源是否释放？ | 真实服务或插件 smoke、断流和卸载 |
| 规范/Skills | 是否有相互冲突规则、虚假完成或不可用命令？ | 链接、schema、真实调用场景 |

## 自审与人工复核

自审优先查失败路径和接口两端，再审查文案与文档是否符合当前代码。保持只读；发现问题先登记，由实现阶段修复。

人工复核只提交需要判断的具体结果：界面可用性、取舍、剩余风险。提供启动入口、重现步骤、期望结果、差异范围，附已确认缺陷处理情况。用户提出新问题时回到实现，不把“已看过”当成“已接受”。没有实际审查者时独立审查一栏标未执行。

## Session 证据审查

执行或模型可见行为变化时，依据 [重放方案](session-replay.md)检查实际请求是否被匹配、录制脚本是否全部消费、父子角色是否稳定匹配，以及新 SQLite/文件结果是否独立比较。审查所有 fixture、prompt/schema、UI 和工作区预期差异；拒绝自动更新快照掩盖缺陷。旧格式输入和当前 writer 预期分别验证，不能混作同一份 oracle。

对目前缺失的 CI、性能和发布验证依照 [差异表](dsh-comparison.md)写未实施，不把文档补齐报告成测试已通过。
