# 与 DeepSeek Harness 的差异核对

核对日期：2026-09-28。上游固定 commit：21638c56315ae6a2b552d6091945d3144c9af32e。范围为已读取的 AGENTS、测试文档、session-snapshot/llm-replay、snapshot 规则及 review/test/notes Skills；不是上游全仓库代码审计。

“已补方案”不等于可运行。当前只有前端测试、静态检查和质量证据脚本；Core、SQLite 和重放仍待实现。

| 方面 | 上游机制 | Ailya 决定与现状 |
|---|---|---|
| Session 重放 | 录制模型驱动真实运行并比较持久化结果 | 先前遗漏；已补双层方案，待 Core 运行器 |
| 模型输入检查 | 提示/schema 和请求相关预期 | 补实际请求匹配；只播响应无法发现 prompt 退化 |
| record/replay/refresh | 不同模式，回放只读 | 已补模式与人工接受候选规则；当前无命令 |
| 文件副作用 | 独立完整工作区预期 | 已补，禁止自动刷新真实文件预期 |
| 历史版本 | 版本化输入及迁移场景 | 已补 SQLite 迁移与导出格式分离，保留旧输入 |
| 父子会话 | 分别保存；模型脚本首次调用顺序绑定有并发限制 | 有意不同：Ailya 用稳定委派关系匹配，待实现 |
| 异常响应 | 覆盖录制无法重建的错误/挂起 | 补按角色与 attempt 的覆盖脚本 |
| 规范化 | 稳定身份和路径，移除不稳定字段 | 补幂等与反例；Ailya 保留问题截止时间和耗时语义 |
| 正式入口 | 场景通过已发布 profile 入口 | 改为 Ailya 正式 Core/Web/API，沿用 Pi，待建设 |
| 覆盖与 CI | 上游有覆盖门槛及多平台流水线 | 不照搬全文件 100%；Ailya CI 尚未配置，关键状态/迁移分支必须有证据 |
| 性能 | 上游有专门性能验证层 | 补性能验收计划，当前没有基准，不能声称性能达标 |
| 模型可见上下文 | 输入可追溯到会话记录 | 补 Core 请求快照/事件关联要求，注意凭据脱敏 |
| 测试可靠性 | 私有资源、清理、竞态同步、负向控制 | 原方案已包含；原型浏览器用例不替代进程/SQLite 测试 |
| 审查 | 版本/范围核实，证据与语义检查 | 原方案已有；本次仍为 self-review，无独立审查或 CI 证据 |
| 经验记录 | 保存决策原因并区分生命周期 | 借鉴；候选验证、人类采纳是 Ailya 设计，不声称 DSH 自动学习 |
| 框架和 SDK | Cordis、多协议/SDK 测试布局 | 不移植无消费者的 SDK/协议测试；保持 Pi/Bun 和当前产品范围 |

## 补充的后续质量层

- CI：实施时分静态、无密钥行为/Session 重放、数据库、浏览器和发布产物；Windows 为本机运行重点，其他目标平台随实际支持范围加入。普通 PR 默认不访问真实模型；真实服务层单独授权和报告。分支保护及 CI 都尚未配置。
- 覆盖：不为覆盖百分比编造测试；对新增状态转换、取消、权限拒绝、迁移/恢复路径说明哪些分支被验证。全套和平台矩阵放 CI；本地按影响选择。
- 性能：建立长会话加载、事件积压、内存、SQLite 搜索和向量查询基线，记录设备、数据规模、冷/热缓存与重复次数。依据真实基线设阈值，不在无测量时编造预算。持续退化需审查，性能样例不能取代功能正确性。
- 请求可追溯：模型看到的系统提示、工具 schema、上下文和参数必须能从版本化快照/事件引用重建；只保留最终回答不够。记录前去除认证信息，测试使用合成或审查过的脱敏内容。
- 验收报告：分别列出规范完成、运行器实现、当前执行证据、未运行项。CI 未建立、密钥缺失或平台未测时不得写全平台通过。
