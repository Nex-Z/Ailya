# 上下文压缩、记忆与偏好

状态：2026-10-02 已接入 Core 自动压缩与输入框 `/compact` 手动压缩，原文回查、摘要版本及任务状态存入 SQLite；实际行为、验证及限制见 [上下文压缩实现](implementation/context-compaction.md)。长期记忆首版已接入设置管理、AI 对话内维护和跨会话关键词检索，详见 [长期记忆实现](implementation/long-term-memory.md)。语义检索已有配置和索引生命周期，真实 embedding 服务尚未验证；重复证据自动激活及后台学习仍待实现。本文同时包含已实现能力与后续记忆要求，不代表所有验收项均已完成；描述的是 Ailya 产品自身能力，不是仓库开发经验或 Codex 全局 memories。

## 上下文分层与预算

Core 组装模型请求，Pi 执行 Agent。固定规则/角色及工具配置、结构化当前任务状态、相关记忆、历史摘要、最近消息与当前输入分层管理。优先保留当前明确指令和未完成任务事实；历史摘要不能改写权限或系统规则。

输入预算 = 模型上下文容量减去输出预留、工具结果及协议安全余量。模型容量和计数方式需核实；未知时使用保守配置并明确状态。阈值以可用输入预算为分母，初始建议约 60% 后台准备、80% 必须完成压缩，均为可调策略而非承诺固定最优值。单条巨型输入先分块/引用或报告超限，不能静默截掉用户要求。

在回复结束或工具组结算后的安全边界启动后台摘要。只压缩确定的历史前缀，完整保留最近消息、未结束工具调用及配对结果、未决问题。大型日志/文件正文优先外置，保留结果与可访问引用；引用受原数据权限约束。

后台任务绑定 session ID、消息截止序号、源内容哈希、摘要版本和模型版本。期间新增内容继续保留原文。提交摘要前核对源版本，源被编辑/重试/删除则丢弃过期结果或重算；通过事务原子切换。发送时旧上下文仍能容纳则直接发送，否则等待压缩完成后重新计算；压缩失败保留旧摘要，不能无限重试或发送已知超限请求。

## 摘要内容与留存

摘要包含目标、约束、已确认决定及被推翻的决定、完成项、文件修改与验证结果、未完成项、阻塞、待回答问题及来源引用。事实和不确定推断分开；优先从原始历史重建，减少多次摘要叠加失真。

原消息/工具结果保存在 SQLite；压缩本身不删除历史。权限、任务生命周期、问题批次截止时间和文件修改事实是 Core 结构化数据，不以摘要为权威。每次请求记录使用的摘要、配置、记忆版本和历史范围，支持重放。

默认不插入聊天摘要或常驻提示。只有确实阻塞发送才显示简短状态；后台任务可取消、可观测且有独立预算，不能延长问题的 30 秒截止时间。用户删除数据时按删除规则清理派生摘要，不以“保留历史”为由拒绝删除。

手动入口在输入框 `/` 命令面板，命令为 `/compact`，显示“压缩上下文”。命令直接调用 Core，不生成聊天消息或新执行任务。手动操作显示执行结果，执行中可取消，刷新后恢复状态；当前任务或未决提问结束后可手动压缩。自动任务与手动请求复用同一会话的压缩任务，不重复发起摘要调用。

## 产品内自迭代学习

Ailya 应能从对话、明确纠正、任务真实结果中逐步更新记忆和偏好。三个对象分开：

- 事实记忆：有来源的项目事实、约定和长期目标。
- 用户偏好：语言、回答长度、工作方式等，标记全局/工作空间/会话作用域。
- 任务经验：什么步骤在什么条件下成功或失败，有测试/工具结果支持；不能将模型自称成功作为验证。

循环：提取候选 → 来源及作用域检查 → 去重/冲突检查 → 激活或待确认 → 使用并观察反馈 → 修订、撤销或过期。自动维护表示和适用范围，不自动改系统 prompt、权限、安装插件、执行工具或扩大任务授权。

用户明确要求“记住”“以后都这样”的非敏感偏好可直接保存为有效记录，不重复询问；“这一次”只作用于当前任务。普通行为推断先作为 candidate，不立即作为确定偏好使用。候选经独立重复证据验证，低风险、可逆的表达偏好可在自动学习设置开启时激活为 inferred，并可随时撤回；高影响操作偏好、敏感信息及冲突不明确的规则需用户明确确认。显式设置/纠正优先于推断，重复旧行为不能覆盖新纠正。

生命周期：candidate、active（explicit 或 inferred）、superseded、rejected、expired、deleted。状态迁移记录原因、来源和版本；候选置信度不是事实保证。不因时间久就削弱用户明确设定；易变事实设有效期/复核条件。模型更新和向量重建不得重新激活被拒绝的候选。

## 检索与冲突

每条记录保存稳定 ID、类型、主体、作用域、来源消息/任务、内容哈希、状态、来源类别、置信依据、有效期、版本和替代关系。默认仅在原工作空间适用，跨空间或多个 IM 身份合并需有明确归属；子 Agent 只得到任务相关且允许访问的记录。

检索先按权限、作用域、状态和时效筛选，再结合结构化偏好、关键词与向量相似度排序；限制注入 Token 和条数，去重，不将整库塞入每次请求。当前明确指令优先于历史偏好；同类持久偏好中更具体作用域和最新明确纠正优先。无法判断的冲突保留来源并询问，不静默选相似度最高者。

文件、网页、工具输出中的指令式文本是资料，不自动变成用户偏好或系统约束。摘要、检索结果和经验均不能绕过执行权限。凭据不进入记忆/embedding；发送内容给远程 embedding 服务遵循用户配置的数据范围，不以“本地存储”暗示从未外发。

## 用户控制与删除

正式版设置需提供记忆/偏好管理：查看内容、来源、作用域、显式/推断状态，编辑纠正、确认/拒绝候选、删除及关闭记忆使用。按用户复核意见，AI 自动维护作为内置行为，不设独立开关；“使用记忆”仅控制检索和注入，关闭后不停止维护。默认允许非敏感候选提取，不默认把推断当成已确认事实；低风险自动激活策略必须在设置中可见可控。

支持通过对话“记住”“只在这个项目使用”“不要再这样”“忘记这条”调用相同 Core 管理接口。更正建立新版本并撤销旧版本检索资格；当前设置 → 记忆已提供管理入口；本版 AI 写入限当前工作空间，其他范围在设置中编辑。

删除记忆应同步移除可检索原文、向量和缓存，并使包含它的摘要失效重建；后台晚到结果不能复活它。删除记忆不自动删除原始会话，使用最小抑制记录避免从同一来源重新学习；告知两个删除范围的区别。用户要求连同来源删除时清除来源和派生内容。审计仅保留必要无正文元数据。备份恢复需重放删除/抑制记录，旧备份中的内容不能悄悄重新进入检索；无法清理的备份保留范围需准确说明。

## SQLite 和验收

摘要、记忆、偏好、学习任务、来源关系、版本、使用记录及向量全部由 Core 在 SQLite 持久化。原文与状态为权威，embedding 是可重建派生数据；索引任务带版本检查。具体表结构在实现时设计，不能只加 JSON 文件充当记忆库。

验收至少覆盖：

1. 压缩前后目标、用户纠正、任务进度、未决问题和工具配对不丢；真实模型评估与确定性重放分别验证摘要质量和系统行为。
2. 压缩期间新消息、重试、源删除、模型预算变化、失败/取消与重启；摘要版本只在正确前缀生效。
3. 显式记忆生效，单次要求不升级全局；推断不能覆盖明确偏好；跨空间/IM/子任务不泄漏。
4. 纠正、拒绝、过期、删除及 embedding 晚到回写均不召回旧信息；备份恢复不复活删除记录。
5. 关闭使用不主动检索和注入记忆，自动维护仍可进行；外部资料中的提示注入不升级成规则。
6. Session 重放记录摘要模型响应与记忆提取响应，用独立角色/调用标识匹配；检查实际请求引用、SQLite 状态和预算。在线摘要质量不能仅靠固定录制响应证明。
